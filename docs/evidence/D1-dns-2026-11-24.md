# Production DNS evidence, 2026-11-24

```powershell
dig +trace status.csc436.com
```

The [captured trace](D1-dns-trace-2026-11-24.txt) follows delegation to
Cloudflare and returns the production app's public addresses. The deployed
application source SHA was not established; DNS is independently managed.
I didn't record the expected result before this check.

I exported the Cloudflare zone again after adding CAA records. The
original export is private pending review because it includes origin targets
and ownership-verification values. A private export is not yet a publicly
accessible submission artifact.

The export identifies the app and MCP hostnames in staging and production as
proxied CNAME records. The following command checked each hostname:

```powershell
foreach ($name in @('status.csc436.com', 'mcp.csc436.com', 'staging-status.csc436.com', 'staging-mcp.csc436.com')) {
    dig '@seth.ns.cloudflare.com' $name A +noall +answer
}
```

The [captured answers](D1-host-ttls-2026-11-24.txt) show a 300-second TTL
for all four public proxied hostnames. Cloudflare sets proxied records to its
automatic five-minute TTL, balancing caching with responsiveness to changes
in its proxy addresses; see its [TTL documentation](https://developers.cloudflare.com/dns/manage-dns-records/reference/ttl/).
This does not document TTL rationale for every other zone record.
