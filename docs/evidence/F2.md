# F2 — Remote loading, empty, and error states

## Claim

The incident board gives visible loading, empty-result, and request-error states for its active remote request, `GET /api/incidents`. The error state provides a retry action.

## Reproduce

From a clean checkout:

```powershell
cd frontend
npm ci
npm run test
npm run typecheck
npm run lint
npm run build
```

## Automated evidence

`npm run test` uses a controlled `fetchIncidents` mock so state transitions do not depend on network timing:

```text
Test Files  1 passed (1)
Tests       2 passed (2)
```

One test holds the request pending, verifies the loading message, then resolves with an empty list and verifies the empty state. The forced-failure test rejects with `Forced test outage`, verifies the error message, retries, and verifies the successful empty state. The frontend source test is `frontend/src/App.test.tsx`.

## Visual evidence

Browser screenshots of the loading, empty, and HTTP 503 error states are attached to the F2 evidence update for this commit. They were captured from the local Vite page against a temporary synthetic API stub: a delayed response for loading, `[]` for empty, and `503 Service Unavailable` for error. The screenshots are direct captures; they were not altered.

## Interpretation and limits

The page visibly distinguishes an in-flight request, a successful response with no matching incidents, and a failed request; the failure can be retried. The board currently uses only the incident-list request. The `createIncident` API helper is not called by this page and has no create form yet, so this evidence does not claim F2 coverage for a create flow.

## AI use and review

Copilot assisted with adding the Vitest state tests and this evidence note. A broad claim that “every API helper has UI states” was challenged: this page only invokes the list request, while the unused create helper is not covered.

## Redaction attestation

The test fixtures and API stub are synthetic, and the screenshots contain no credentials or real personal or institutional data.
