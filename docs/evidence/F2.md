# F2 — Remote loading, empty, and error states

## Claim

Remote operations expose visible progress and failure states: incident loading and retry, sign-in-status loading/error, report submission progress/errors, and operator update/publish/archive progress/errors. Public incident reads include only published, non-archived reports; authenticated operators also receive private submissions awaiting review.

## Reproduce

From a clean checkout:

```powershell
cd frontend
npm ci
npm run test
npm run typecheck
npm run lint
npm run build
```

## Automated evidence

`npm run test` uses controlled API and `EventSource` mocks so state transitions do not depend on network timing. The tests verify loading, empty, forced-failure/retry, viewer submission privacy, operator controls, authenticated CSRF submission, and live-update deduplication. The frontend tests are under `frontend/src`.

## Visual evidence

Browser screenshots of the loading, empty, and HTTP 503 error states are attached to the F2 evidence update for this commit. They were captured from the local Vite page against a temporary synthetic API stub: a delayed response for loading, `[]` for empty, and `503 Service Unavailable` for error. The screenshots are direct captures; they were not altered.

## Interpretation and limits

The public board remains usable without signing in. Signed-in viewers can submit incidents for private IT review; only operators see the pending queue and can publish, edit, or archive entries. Submission/update errors are shown in the associated form, and successful actions have visible status messages.

## AI use and review

Copilot assisted with adding UI and API tests and this evidence note. API helpers without a user-facing workflow are not claimed as covered.

## Redaction attestation

The test fixtures and API stub are synthetic, and the screenshots contain no credentials or real personal or institutional data.
